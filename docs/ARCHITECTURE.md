# Architecture notes

Vanilla JavaScript (ES modules), IndexedDB for storage, a generated service worker for offline use. No build step
for the app itself and no dependencies; Node is used only for tooling and tests.

## Layout

    index.html, manifest.webmanifest, sw.js   app shell (sw.js is generated by tools/build.mjs)
    js/version.js            the one place the version number lives
    js/engine/               pure functions: Latin forms, form index, answer checker, prompt helpers (items.js)
    js/core/                 storage (store.js), scheduler, modes, session runner, content loader, export/import
    js/ui/                   screens: home, session, progress, settings, words; modes.js = how drill modes talk
    js/modules/registry.js   the list of tracks
    content/                 all Latin (see docs/CONTENT.md)
    tools/                   validate, generate, build, release, ids, flags
    tests/                   node unit tests; tests/e2e = Playwright browser tests (lib.py is the shared bot)

Rule of thumb: `engine/` and `core/` never touch the DOM, so they are tested in Node; `ui/` only draws.

## Data flow

1. `core/content.js` loads the lexicon, skills and every pack listed in `registry.js`, prepares each item
   (`engine/items.js`: capitalizes sentence starts, builds accepted variants) and resolves pack gates
   (`requires`).
2. `core/scheduler.js` holds the learning ladder and unit unlocking: box and due date per item, level
   (0 choose, 1 fill, 2 write), `unitUnlocked`, `lockReason`, `summarize`.
3. `core/modes.js` builds a session's queue. `buildQueue(ctx)` dispatches on `mode`.
4. `ui/session.js` runs the queue; `core/session.js` records each result (box, mistakes, activity).
5. `core/store.js` persists state to IndexedDB; export/import is schema 1 and merges by timestamp.

## Modes

`core/modes.js` has one table:

    MODES = { continue, unit, weak, mistakes, speed, narrate, dialogue, swap }

Each mode has `build(ctx)` returning queue entries. Modes that replay a unit (`drill: true`) also have
`replay: 'Button label'`; a unit with `"play": "<mode>"` in its pack.json entry shows that button once 80% of it is
met. Drill entries carry `mode`, `nosched: true` (a correct answer is recorded as practice and never changes the
schedule; a wrong one still cuts the box and logs a mistake), and optional `timed`, `step`, `of`.

`ui/modes.js` is the matching table of **presenters**: the eyebrow line above each exercise, the title on the
summary, an optional score line and an optional recap (the narration paragraph, the conversation transcript).

**To add a mode:** one builder and one table entry in `core/modes.js`, one presenter in `ui/modes.js`. If it needs a
button on a unit, set `replay` and give units `"play"`. Add a test in `tests/modes.test.mjs`.

## Tracks and gates

A track is `content/<name>/pack.json` plus unit files plus one line in `registry.js`. `pack.json` may carry
`requires: {pack, unit}`: the track stays locked until 80% of that unit has been met (`lockReason` supplies the
tooltip). Settings can pause a track (`settings.pausedPacks`): Continue stops adding its new sentences, reviews
continue.

New sentences per session are one shared budget (default 6) divided among unlocked, unpaused tracks.

## Item types and how they are shown

`promptKind(item)` returns `question` (has `q`), `swap` (has `swap`), `situation` (has `sit`) or `plain`.
`promptText` and `cueText` give the prompt and the line under it; `promptKey` is what must be unique app-wide.
Conversation turns are ordinary question items; `priorTurns` and `sceneOf` supply the transcript.

## Service worker and versions

`node tools/build.mjs` precaches every app file (not the `gen/` templates) under a cache name that is a hash of the
files, so any change makes devices fetch the new version. It must run after ANY app-file change; `tools/release.mjs`
does it for you. It also copies `js/version.js` into `package.json`.

## Tooling

| command                           | what it guards                                                                  |
| --------------------------------- | -------------------------------------------------------------------------------- |
| `tools/validate.mjs`              | every word is in the lexicon, distractors are wrong, prompts unique, modes known  |
| `tools/ids.mjs check`             | no shipped sentence id disappears (progress is keyed by id)                       |
| `tools/generate.mjs`              | templates to unit files, append-only                                             |
| `tools/release.mjs`               | all of the above plus tests, build, version bump and zip, in a safe order         |
| `tools/flags.mjs <export>`        | turns your flags and repeat mistakes into a fix list                              |
| `tests/*.test.mjs`                | engine, scheduler, modes, storage, generator, tooling                             |
| `tests/e2e/*_test.py`             | the real app in Chrome at phone size: every unit played, offline, import/export   |

## Known limits

- Content is unreviewed by a Latin teacher.
- Not tested on a physical phone (tested in desktop Chrome at phone size).
- Progress lives in the browser; export regularly.
